# FUT27 — App personal estilo FUT.GG / FUTBIN para EA FC 27

Fecha: 2026-09-27 · Autor: Renato Rivera · Estado: aprobado en conversación, pendiente revisión escrita

## 1. Objetivo

App web personal (un solo usuario, sin registro, sin anuncios) que replica la lógica de FUT.GG y FUTBIN
para EA FC 27 Ultimate Team, con precios del **mercado de PC**. Accesible desde PC y celular.

Criterio de éxito: Renato puede, desde el navegador,
1. buscar cualquier carta de FC 27 y ver su precio PC (real o estimado, siempre etiquetado);
2. armar un equipo con química FC 27 correcta, rating y costo;
3. resolver un SBC activo al menor costo, usando su club o comprando todo;
4. ver cómo se mueve el mercado (historial, subidas/bajadas, pisos por valoración).

Fuera de alcance: multiusuario, consolas, trading automático, login automático en EA, compra/venta automatizada.

## 2. Restricciones y decisiones

| Decisión | Motivo |
|---|---|
| Todo en Cloudflare gratis: Workers (cron + API), D1, Pages | Costo 0, ya usado por Renato en La Fecha Futbolera |
| Precios **gratis**: PC por captura propia + consola de FUT.GG como referencia | Elegido por Renato; el precio por carta de FUT.GG y todo FUTBIN están bloqueados por Cloudflare sin navegador real, y los precios libres de FUT.GG son de consola |
| Club vía bookmarklet ejecutado manualmente en la Web App de EA | Login automatizado inviable (captcha/2FA) y riesgoso para la cuenta |
| El bookmarklet **no hace peticiones propias** al mercado de EA | Evitar bloqueos/sanciones; solo lee respuestas que el navegador ya recibió |
| Resolvedor de SBC en el navegador (HiGHS WASM) | Sin costo de servidor ni límites de CPU del Worker |
| Worker gratis: máx. 50 subrequests por invocación | Sincronización por lotes con cursor persistido en D1 |
| D1 gratis: 100.000 escrituras/día | Historial de precios solo guarda cambios |

## 3. Arquitectura

Repositorio `C:\Proyectos\fut27` (privado en GitHub `RenatoRiveraFIT/fut27`), monorepo npm workspaces:

```
worker/      Cloudflare Worker: handlers cron (scraping) + API REST JSON para la web
web/         Vite + React + TypeScript, publicado en Cloudflare Pages
shared/      Tipos y lógica pura compartida: química, precios estimados, parser de requisitos
solver/      Resolvedor de SBC (modelo MILP sobre HiGHS WASM), corre en el navegador (Web Worker)
bookmarklet/ Script para la Web App de EA: exporta club y captura precios vistos
```

Flujo: cron del Worker → FUT.GG / EA JSON → D1 → API del Worker → web. El bookmarklet hace POST a la API
del Worker con un token personal (secreto `IMPORT_TOKEN`). La API de lectura es pública; las de escritura
(importar club, alertas, equipos guardados) exigen ese token, que la web guarda en `localStorage`.

## 4. Fuentes de datos (verificadas el 2026-09-27)

Base FUT.GG: `https://www.fut.gg/api/fut/` (requiere User-Agent de navegador, barra final en las rutas).

| Dato | Endpoint | Frecuencia |
|---|---|---|
| Cartas (~19.900, 30 por página) | `players/v2/27/?page=N&overall__gte=A&overall__lte=B` — la API corta en 10.000 resultados por consulta, así que se recorre por tramos de valoración | ciclo diario, lotes chicos por minuto con cursor |
| Detalle de carta (stats, PlayStyles) | `player-item-definitions/27/{eaId}/` | bajo demanda, cacheado en D1 |
| Pisos por valoración | `market/cheapest-price-per-rating/`, `market/27/cheapest-by-rating/v2/overview/` | cada 15 min |
| ~11 cartas más baratas por valoración 81–93 con precio | `market/27/cheapest-by-rating/v2/overview/` | cada 15 min |
| Cambios de rango de precio de EA | `market/price-range-changes/` | cada 1 h (fase 5) |
| SBCs | `sbc/27/?page=N`, `sbc/27/{slug}/` | cada 1 h |
| Evoluciones | `evolutions/v2/27/v3/all/?page=N` | cada 1 h |
| Nombres oficiales, equipos, ligas | EA `…/web-app/content/{fut_guid}/2027/fut/items/web/{players,teams,leagues}.json` | diaria |

El `fut_guid` se lee del HTML de la Web App de EA (no se deja fijo en el código).

Riesgo: FUT.GG puede cambiar o bloquear endpoints. Mitigación: cada fuente registra su último éxito/error en la
tabla `source_status`; la web muestra el último dato válido con su fecha; los parsers validan forma (zod) y
fallan de forma explícita sin sobrescribir datos buenos.

## 6. Precios

Cada precio mostrado tiene etiqueta `real` (FUT.GG o captura propia) o `estimado`.

Hallazgo (2026-09-27): los precios libres de FUT.GG no cambian con `platform=pc`; se tratan como **consola**.
`players/v2/momentum` devuelve cartas de FC 26 y no se usa.

Etiquetas posibles: `pc` (captura propia), `consola` (FUT.GG), `estimado` (piso de consola de su valoración),
`no_transferible`, `sin_precio`.

- Prioridad: captura PC de menos de 24 h > captura PC más antigua (con su fecha) > consola FUT.GG > estimado.
- Estimado = piso de consola de la valoración × factor de rareza (`shared/src/config/price.ts`; 1.0 para
  rarezas `Common` y `Rare`). Cartas especiales sin precio → `sin_precio` (se muestra "desde {piso}" como pista).
- Captura PC: la hace el bookmarklet (fase 3) leyendo las búsquedas que Renato hace a mano en el mercado.
- Cartas intransferibles (SBC, objetivos, evoluciones) no tienen precio de mercado: se muestran como "no transferible".

## 7. Módulos y pantallas

1. **Cartas** `/jugadores`, `/jugador/:id`: buscador con filtros (posición, valoración, liga, club, nación,
   rareza, PlayStyles, ícono/héroe, rango de precio, "en mi club"); ficha con stats, posiciones, versiones
   del mismo jugador (`base_ea_id`), precio y gráfico.
2. **Mercado** `/mercado`: mayores subidas/bajadas (24 h), pisos por valoración 81–91 con tendencia,
   alertas de precio (en la app; push opcional en fase 5).
3. **Armador** `/equipos`: formaciones FC 27, cancha con arrastrar y soltar, química por jugador y total,
   rating del equipo, costo total, guardar varios equipos, generador automático por presupuesto y ligas.
4. **Mi club** `/club`: cartas importadas, intransferibles, duplicados, valor total.
5. **SBCs** `/sbc`, `/sbc/:slug`: lista activa con requisitos, recompensa, costo PC, vencimiento; botón
   "Resolver" (usar mi club primero / comprar todo); indicador "¿conviene?" = costo vs. valor esperado de
   la recompensa.
6. **Extras** `/evoluciones`: evoluciones activas, qué cartas de mi club califican, resultado de la mejora.
7. **Estado** `/estado`: último éxito/error por fuente.

## 8. Química (shared/chemistry)

Función pura `computeChemistry(squad, formation) → {perPlayer[11], total}`.

- Umbrales en `shared/config/chemistry.ts` (valores iniciales FC 27: club 2/4/7, liga 3/5/8, nación 2/5/8;
  **a verificar en el juego**, en particular el de club, que otras fuentes dan como 2/5/8).
- Solo cuentan jugadores en posición (posición principal o alternativa). Fuera de posición: 0 y no aportan.
- Máximo 3 por jugador, 33 por equipo.
- Íconos: química completa en posición; +1 a cada liga; aporte a nación +1.
- Héroes y Hall of FUT: química completa en posición; aporte a su liga +1; nación +1.
- Entrenador: +1 si comparte liga o nación (tope 1) — se modela en el armador, no afecta SBCs.

## 9. SBCs

- **Parser** `shared/sbc/parseRequirements(text[]) → Requirement[] | Unsupported`. Soporta al menos:
  min/max/exact de ligas, clubes, naciones, rareza, jugadores de una liga/club/nación/rareza concreta,
  mismo club/liga/nación (max/min por grupo), rating mínimo del equipo, química total mínima, cantidad de jugadores.
  Texto no reconocido → el reto queda `supported = false` y la web lo indica. Los textos desconocidos se
  registran para ampliar el parser.
- **Solver** `solver/`: MILP (HiGHS WASM en un Web Worker).
  - Variables binarias por (carta candidata, posición del once).
  - Restricciones: una carta por posición, sin repetir jugador base, requisitos parseados, rating del equipo
    (fórmula oficial de rating de equipo con ajuste por encima del promedio), química mínima (linealizada con
    variables de conteo por club/liga/nación y umbrales).
  - Objetivo: minimizar costo; carta de mi club cuesta 0 (modo "usar club") o su precio de venta
    (modo "comprar todo" excluye el club).
  - Candidatas: se podan a las N más baratas por (valoración, liga/nación relevante) para mantener el modelo chico.
  - Límite de tiempo (10 s por defecto). Si no llega al óptimo, devuelve la mejor solución encontrada marcada como tal.
- Referencia de modelado: github.com/Regista6/EA-FC-Automated-SBC-Solving.

## 10. Bookmarklet

Se instala arrastrando un enlace desde `/club` a la barra de favoritos. Ejecutado dentro de la Web App de EA:
1. Envuelve `fetch`/`XMLHttpRequest` para leer respuestas que la propia Web App recibe (club, búsquedas de mercado).
2. "Exportar club": recorre las páginas del club **usando la navegación normal de la Web App**, sin peticiones propias.
   Si la Web App no expone un camino sin peticiones extra, se acepta paginar el club con las mismas llamadas que
   hace la Web App al abrir el club, con pausas de 2–3 s, disparado solo por Renato.
3. Envía los datos al Worker (`POST /api/club`, `POST /api/prices/capture`) con el token personal.

## 11. Errores y observabilidad

- Cada job cron: try/catch por fuente, escribe `source_status`, nunca borra datos si la respuesta es inválida.
- API: respuestas JSON `{error}` con código HTTP correcto.
- Web: estados de carga/error/vacío en cada pantalla; precios con fecha de actualización.

## 12. Pruebas

- Vitest en `shared/`, `worker/`, `solver/`.
- Fixtures: respuestas reales de FUT.GG guardadas en `worker/test/fixtures/` (sin red en los tests).
- Química: casos conocidos (equipo mono-liga, íconos, fuera de posición).
- Parser: todos los `requirementsText` de los SBC activos al 2026-09-27 como casos.
- Solver: SBCs reales con pool de candidatas fijo; se verifica que la solución cumple todos los requisitos.
- Worker: pruebas con `@cloudflare/vitest-pool-workers` y D1 local.
